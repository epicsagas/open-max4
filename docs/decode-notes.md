# PJM.021/022/023 인코딩 해독 노트

2026-08-15 세션 결과. 다음 해독 세션의 출발점.

## 확정 사실

1. **구조**: 헤더 "N 문장" + 라인들. ASCII(숫자/공백/CR/LF/`.`/`?`/`!`/`[`/`]`/`~`/영문)는 평문 그대로, 한글만 미지 2바이트 코드.
2. **치환 기호 `[0`~`[4`** (0x5B + 숫자) — DATA.DOC 규칙과 일치:
   - `[0` 이,가 / `[1` 을,를 / `[2` 은,는 / `[3` 이,없음 / `[4` 없음,없음
   - 받침 여부로 앞/뒤 선택. 기호 뒤 공백이 올 수 있음 (`[4 [b565]...`).
3. **PJM.021과 PJM.022는 대부분 동일 라인을 공유** (1인칭/2인칭 변형만 일부 다름).
4. 강한 증거: `9461` = '다' (`[3[9461]` = "[3다" 다수), `9c61 89a1` = '라는'.
5. **표준 인코딩 아님**: 상용(KSSM)·삼성·금성·도깨비II·KS1987·KS1기·한컴 테이블 전부 불일치 (charset.fandom machine-readable 테이블로 검증). 바이트 분포는 2바이트 고정 쌍, b1 ∈ 0x84~0xD3, b2 ∈ 0x41~0xF5.
6. Max4.exe 포인터 테이블: 파일 0x13DF2에 (off, seg=0x12D5) far pointer 10개 — pjm.001~032 문자열 지목. 로드 후 변환 루틴은 미추적.

## js-dos 평문 대조 ('바보' 입력, PJM.022 계열)

에뮬레이터로 원본을 실행해 얻은 응답 6줄을 바이트열과 대조했다.
원문은 이 문서에 옮기지 않는다. 대조로 확인된 구조만 적는다.

- 6줄 모두 조사 치환 기호(`[2`, `[3`)를 포함한 템플릿에서 생성된다.
- 확인된 형태: `[2 자신이 [3라는 것을 모르지`, `너야말로 [3다.` 처럼
  입력 명사가 문장 안 두 자리에 각각 치환된다.
- 정확한 hex 라인 매칭은 아직 못 함 — 블록 위치('바보'가 023에서 몇 번째 그룹) 미확정.
